# 简易 CRM 使用与发布

入口沿用 `/admin` 和现有后台账号。官网、人工新增与表格导入共用一份线索库；等级使用 A 服务中、B 跟进中（待联系或洽谈中）、C 潜在客户池、D 已流失、E 无效。C 用于同类有价值需求，但当前我们暂时无法满足的潜在客户。默认展示全部渠道的 A/B/C。

## 日常使用

1. **新增线索**：填写名称与至少一种联系方式，选择渠道；其他渠道还需填写来源说明。默认 B。可补录首次联系、初始跟进和下次计划。人工录入不会触发官网垃圾分类，也不会发送询盘通知。官网有效新询盘同样默认 B，明确垃圾为 E，C/D 由人工按实际业务情况判断。
2. **查看与筛选**：按渠道、等级、关键字、导入批次和跟进状态组合查询。统计卡不受当前等级选择限制，其余筛选与列表一致。今日待跟进为上海当天的计划，已逾期为当前时刻之前未更新的计划；两者可有重叠，只针对 A/B/C。D 已流失可单独筛选查看，不再进入默认工作队列。
3. **跟进**：点开线索，填沟通时间、方式和内容，点击“添加跟进”。沟通时间可以补录，录入时间与账号由系统记录。每次追加，不覆盖历史。写错可追加更正记录。
4. **计划与等级**：当前下一步、下次时间可替换或清空。“仅更新计划/等级”不产生沟通记录，但会保留操作历史。完成本次跟进后应设置新的计划或清空旧计划，避免持续显示逾期。
5. **资料编辑**：支持修正基本信息；官网原始留言与来源追踪只读。两处页面同时编辑，后保存的过时版本会被拒绝，请保留未保存内容，重新加载详情后重录。
6. **导出**：线索 CSV 与完整跟进 CSV 均按当前筛选导出。后者包含全部沟通、计划变更和历史备注，不只是最新一条。

历史备注迁移为“时间未知”的独立条目，保留原字段，不推断真实沟通时间。原有已发通知、线索 ID 和 UTM 不改写。以当前共享账号记录操作者，不能区分使用同一账号的不同人员。

等级定义升级时一次性把旧 D（待联系）转入 B，把旧 C（已流失）转入 D，A/B/E 保持不变；每条转换都有时间线记录，并增加版本号阻止旧页面覆盖。历史沟通中的等级快照保留旧制解释。升级可重复执行，不会再次把新的 D 已流失转成 B。升级前未完成的导入预览会失效，需要按新定义重新导入。

## 导入

先点“下载导入模板”，使用 Excel 填写后另存为 `.xlsx` 或 **CSV UTF-8**。也可使用自己的表格，在预览前映射列。旧 `.xls`、宏工作簿不支持；不上传聊天截图或报价附件。

- 文件不超过 5 MiB，每张工作表最多 1,000 条线索、50 列；可选择要导入的工作表。日期使用 `YYYY-MM-DD HH:mm`，无时区日期按上海时间解释；也支持带时区的 ISO 日期。不猜测 `10/11/2026` 等模糊格式。
- 电话、微信、WhatsApp 号码应在 Excel 中设置为**文本**，以保留前导零和长号码。若 Excel 已将原号码改为数值或科学计数法，系统无法还原丢失的数字。
- 映射“姓名/线索名称”和至少一个联系方式；可映射公司、国家、产品、应用、需求、渠道、等级、首次联系、下次计划及一条初始跟进。未知列可以忽略，同一字段不能映射多列。
- 渠道可填写后台显示名称或 `website/wechat/whatsapp/email/linkedin/tiktok/exhibition/b2b/referral/other`。空渠道必须选择本批默认渠道；其他渠道填写来源说明。空等级默认为 B。若使用旧版导出的表格，重新导入前须先将旧 C 改为 D、旧 D 改为 B；系统不会猜测外部表格使用哪一版等级定义。新版线索导出包含等级名称与定义版本，跟进导出也标明记录所属版本。
- 先预览，查看有效行、重复项和错误行。错误行可下载修正；重复项默认不选。确认是新需求才勾选对应重复行，不会合并或覆盖旧资料。同名或同公司不会自动合并。
- 预览后若相同联系方式新增进库，确认会被阻止，需重新预览。确认操作以事务完成，重复提交同一批次只返回原结果。
- 草稿 30 分钟失效；主动取消或关闭导入窗口会取消草稿，过期草稿每分钟清理。上传原文件不保存，临时解析行保存在受保护的数据库中；完成后删除暂存行，只保留文件名、时间、操作者和结果摘要。
- 完成后自动筛选到该批线索，可通过“导入批次”切回全部。人工导入均不发送邮件或飞书通知。

## 发布与运维

### 订单、最终合同与发货

主页提供“线索管理”和“订单管理”两个独立入口，分别为 `/admin` 与 `/admin/orders`，订单详情为 `/admin/orders/:id`。订单页统一展示所有客户的订单，不受线索等级或渠道筛选影响；支持订单号、客户、公司、规格、物流单号搜索及订单状态筛选，每页 20 笔，默认最新录入优先。最后一列为“操作”，分别点击“查看”或“编辑”；合同和发货资料留在详情页，不在操作列重复展示。

在线索列表点击该行“下单”，或打开线索详情点击“为此线索下单”。保存成功后直接进入独立订单详情，后续编辑、合同上传/预览/下载、发货维护均在订单页操作，订单列表不提供脱离线索的新建入口。客户档案就是当前线索，修改客户信息仍使用“编辑基本资料”，不会另建一份客户资料。同一线索可以保存多笔订单，每笔订单可以有多个规格明细。

线索详情用“线索信息与跟进 / 关联订单”两个 Tab 分区：前者只显示资料、跟进和等级计划，后者列出此线索的全部订单摘要及进入订单详情的链接，并可展开订单操作记录。切换 Tab 不重新创建表单，尚未保存的跟进内容会保留。订单详情可返回来源线索，并直接打开其订单 Tab。直接刷新订单列表、订单详情仍可访问，均要求原有后台登录。

- **规格**：片材必填长度、宽度、厚度（均为 mm）与整数片数，例如 `276 × 148 × 1.8 mm，20000 片`。卷材必填长度（m）、宽度/厚度（mm）及整数卷数。最多 50 个明细，每个明细可选填每片/每卷单价；单价使用订单币种。
- **订单**：订单编号必填且全库唯一；填写最终确认总金额和三字母币种（例如 CNY/USD）。总金额由人工确认，系统不自动按单价合计，不跨币种汇总。可填写约定交期、备注。
- **进度**：待确认、已确认、备货中、已发货、已完成、已取消。通过“编辑订单 / 发货”修改；已发货/已完成必须有发货日期，可填物流公司与单号。日期按上海当地日历日期记录。第一版整单发货，不拆分批次，也不增加收付款/库存模块。
- **合同**：可在下单时先上传识别，也可保存订单后再上传一份最终确认文件。最终文件支持 PDF、PNG、JPG/JPEG、DOC、DOCX，最大 10 MiB；PDF/图片由浏览器直接预览，Word 下载查看，不接入外部文档转换。建议使用 PDF；不支持 PDF 内置预览的浏览器可下载查看。文件头与扩展名必须匹配，但这不是病毒扫描，请只上传可信文件。
- **替换合同**：必须勾选确认，仅保留当前最终文件；旧文件不会作为版本库保留。操作时间线保留替换前后文件名与 SHA256 校验值。错误资料通过编辑纠正，没有删除订单入口。
- **记录与安全**：新增/编辑订单、改变状态、上传/替换合同均追加线索时间线，并保留操作者及时间，不改变线索等级、不发送询盘通知。已有订单的线索受历史垃圾复查工具保护，可疑内容只列入人工复核，不自动降为 E。不同页面同时修改订单或合同，过时版本被拒绝。新增表单具有重复提交保护。合同预览和下载均校验后台登录，不能通过公开静态目录访问。

订单与合同数据分别在 `crm_orders`、`crm_order_contracts` 中保存；合同原件作为 SQLite BLOB 保存在同一受保护数据库内，不额外建立公网上传目录。现有 SQLite 备份同时包含订单和合同，合同较多后备份体积会增加。完整跟进 CSV 会包含订单操作及前后变化，但不包含合同文件本身；恢复合同必须恢复数据库备份。

### 从合同识别订单号

1. 在线索发起“下单”，选择可复制文字的 `.pdf` 或 `.docx`，点击“识别合同编号”。此步骤不会创建订单，不会修改客户资料。
2. 服务端本地提取正文及 Word 页眉/页脚，寻找明确的“合同编号 / 合同号 / Contract No. / Contract Number / Agreement Number”等标注。不从文件名、发票号或联系电话猜测合同号。未找到编号时可手工录入。
3. 只有一个且未重复的编号、订单号输入框为空时会回填；已经手工填写的订单号不自动覆盖。多个候选需点击“使用此编号”选择。同号已有订单时提示现有订单，不覆盖、不合并，确认保存仍进行唯一性校验。
4. 人工核对编号，填写规格、数量、金额等其他字段后保存。订单与这份合同在同一事务中保存，不需再上传一次；原文件字节保持不变。保存失败不产生半笔订单，重复确认不重复创建。
5. 取消所选合同或关闭表单会清理合同草稿；30 分钟后过期，每分钟及下次请求时清理。原件暂存在 `crm_order_contract_drafts`，按当前账号与来源线索隔离，同一账号最多三份。丢失响应或关闭浏览器的草稿也会到期清理。PDF/Word 原文不发送给外部 AI，也不写入日志。

识别只用于辅助录入**合同编号**，不自动提取金额、规格或数量，不自动确认订单。扫描件、图片及旧 `.doc` 不支持识别，仍可手工建单后上传作为合同。文件上限 10 MiB；PDF 最多 50 页，文字提取上限 100 万字符，Word 相关 XML 解压上限 8 MiB。解析在限时 15 秒、192 MiB JavaScript 堆的工作线程内执行；加密、损坏、超限或无明确编号时提示手工核对，不自动猜值。

本次实现与本地预览不代表已发布。发布范围为 `server/`，使用现有询盘 API 部署流程；前端静态站点部署不能更新本后台。发布前备份 SQLite，现有工作流在重启前执行备份并验证。

启动时执行可重复的数据迁移，增加 CRM 字段、`crm_activities`、`crm_import_batches`、`crm_orders`、`crm_order_contracts` 及 `crm_order_contract_drafts`，迁移旧备注及旧下次跟进日期。迁移中保留无法解释的旧日期，需后台人工修正。部署时同步后台 Nginx 配置，允许 11 MiB 请求包；应用仍限制线索导入为 5 MiB，合同为 10 MiB，官网公开表单保留 32 KiB 请求限制。新增后台 JSON 接口上限 96 KiB。

数据库内的线索、跟进、草稿和导入摘要均包含客户资料，应沿用现有数据库权限和备份策略。备份整个 SQLite 数据库即可覆盖 CRM，无独立上传目录。

验证命令：

```sh
npm ci --omit=dev --prefix server
npm audit --omit=dev --prefix server
npm test --prefix server
git diff --check
```

本次使用兼容 Node 20 的解析依赖；新增合同文本识别要求 Node **20.19.0 或更高版本**，已在 Node 20.19.0 验证 PDF 文字提取。上线前核对服务器版本，不自动升级生产运行环境。回退部署前应先停服；不要在新增 CRM 数据后直接还原旧备份，否则会丢失备份后的录入与跟进。
